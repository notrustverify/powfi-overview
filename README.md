# PowFi Round 0 Dashboard

A static, no-backend dashboard for the PowFi Round 0 campaign on [Alephium](https://alephium.org):
xALPH liquid staking plus the ALPH farming pools. Every number is read live from
mainnet in the browser — there is no server or API key.

## What it shows

- **xALPH liquid staking** (`225WevmFp5ZgzPsyVJTvyp2v2uyKrvp329HfrVmzffnWj`) — ALPH staked vs.
  the 20.5M target, share of circulating ALPH, and the xALPH:ALPH redemption rate.
- **ALPH × USDT farming pool** (`xRF7AKLwpGjWzDpFFnUkdXBALKtotFcnD5XFf2EAyioZ`) — pool TVL vs.
  the $200k target, implied ALPH price, and raw reserves.
- **xALPH × ALPH pool** (`22QumTFozFy6HyndPMna2t4KjjVNGYNATgY2reeV2d6nj`) — TVL and market
  price vs. the vault's redemption rate (peg deviation).

A second page, `activity.html`, lists the vault's most recent stake / unstake / reward
events, decoded straight from its on-chain event log (no private API involved).

Data sources, all called directly from the client:

| Source | Used for |
|---|---|
| `node.mainnet.alephium.org` (via `@alephium/web3`'s `NodeProvider`) | contract state / reserves |
| `backend.mainnet.alephium.org` (via `@alephium/web3`'s `ExplorerProvider`) | circulating ALPH supply, token metadata |
| `api.powfi.alephium.org` | pool spot prices and TVL (ALPH/USD comes from the ALPH × USDT pool) |

The campaign targets (20.5M ALPH staked, $200k pool TVL, 5%/15% target APYs, 15% of
circulating ALPH) are fixed constants in `src/chain.ts` — update them there if a new round changes them.

## Generate a shareable staking distribution image

The standalone script `misc/scripts/staking-distribution.py` fetches the xALPH vault's
staking events and creates an **1800×1200 PNG** plus an editable SVG. It does not
add anything to the dashboard.

![PowFi staking distribution: cumulative ALPH deposits per recipient address](output/staking-distribution/powfi-deposit-distribution.png)

Generated by the script from the snapshot dated in the image. Running the script
with the default output directory refreshes this preview.

### First-time setup

Use Python 3.10 or newer. From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r misc/scripts/requirements-staking-distribution.txt
```

### Generate the image

Each run fetches fresh event history from the default public mainnet node:

```bash
python misc/scripts/staking-distribution.py
```

In a new terminal, activate the environment again with `source .venv/bin/activate`
before running the script.

To select a fullnode, pass its base URL with `--fullnode` (`--node-url` is an alias):

```bash
python misc/scripts/staking-distribution.py --fullnode https://node.mainnet.alephium.org
```

For a locally running mainnet fullnode:

```bash
python misc/scripts/staking-distribution.py --fullnode http://127.0.0.1:12973
```

The selected node must be synced to **Alephium mainnet** and expose the vault's
complete indexed contract-event history through `/events/contract/...`. Pass the
base URL, without an `/events` suffix. This script assumes an API accessible
without authentication.

To change the output directory:

```bash
python misc/scripts/staking-distribution.py --output-dir ./output/share
```

Options can be combined. Run `python misc/scripts/staking-distribution.py --help`
for the full list, including replaying previously saved events offline.

### Output and calculation

By default, files are written to `output/staking-distribution/`:

- `powfi-deposit-distribution.png`: the shareable 1800×1200 image.
- `powfi-deposit-distribution.svg`: the scalable chart.
- `summary.json`: address counts, mean, median, distribution bins and methodology.
- `staking-events.json`: deduplicated source events for reproducibility.

Running again replaces these files; use a different `--output-dir` to preserve a
previous snapshot.

**All deposits to the same recipient address are added together into one
observation.** For example, deposits of 100, 500 and 1,000 ALPH to the same address
count as one address with 1,600 ALPH deposited. The mean, median and size ranges
are calculated from these combined address totals. The two charts show the
number of addresses in each range and their share of all deposited ALPH.

The script reads only `Staked` events, removes duplicate event records, and
retains exact integer attoALPH amounts until display conversion. It captures the
node's event cursor count before pagination so incoming deposits do not shift
the snapshot.

These are **cumulative gross deposits**, not current wallet balances. Withdrawals,
xALPH transfers, rewards and unstake cancellations are not added or subtracted.
One address is not necessarily one person. The image includes the snapshot date
and these calculation notes.

## Deploy to GitHub Pages

A workflow at `.github/workflows/deploy.yml` builds and publishes `dist/` on every push to
`main`. To enable it:

1. Push this repo to GitHub.
2. In the repo's **Settings → Pages**, set **Source** to **GitHub Actions**.
3. Push to `main` (or run the workflow manually from the Actions tab).

The workflow sets Vite's `base` to `/` for the custom domain
`https://powfi.notrustverify.ch`. Configure that hostname in **Settings → Pages →
Custom domain**. Asset URLs must start at the domain root, without `/powfi-overview/`.

If switching back to a `https://<owner>.github.io/<repo-name>/` project URL, change
the workflow's `VITE_BASE` to `/<repo-name>/` and rebuild.
